# cat 引擎 — 架构总览

> 目标读者：对实时渲染 / 游戏引擎已有基本认知（熟悉 Unity / UE / 自研引擎其一即可）的 C++ 开发者。

## 1. 项目定位

`cat` 是一个面向学习和实验目的的轻量级 3D 引擎，强调 **小而清晰**：

- 渲染后端以 **Vulkan** 为主（保留了 OpenGL ES 代码痕迹但不再使用，`def.h` 默认开启 `TEST_VULKAN`）。
- 资源以 **glTF 2.0** 为唯一模型/动画交换格式（通过 cgltf 直接驱动场景图构建）。
- 自带极简编辑器（基于 ImGui + ImGuizmo），具备场景树、属性面板、Gizmo 操作、Pick Pass 拾取等。
- 自带 STL 替代品 `scl`（容器 / 数学 / 文件 / 线程），所有上层模块统一使用，不依赖标准 STL 的容器。

整体设计目标是**让每一层职责清晰可替换**：`IRender` 接口隔离图形 API、`Env` 集中管理全局资源、`Scene`/`Object` 形成单向引用的场景图。

## 2. 模块分层

整体分四层，自底向上：

```
┌─────────────────────────────────────────────────────┐
│  testCat   (应用层 / 编辑器：窗口、GUI、相机、主循环)        │
├─────────────────────────────────────────────────────┤
│  catui     catwindows     (UI 控件扩展、Win32 窗口/输入)   │
├─────────────────────────────────────────────────────┤
│  cat       (引擎层：场景图、资源、动画、shader 缓存)         │
│  catvulkan (Vulkan 实现 IRender；管线、描述符、命令缓存)    │
├─────────────────────────────────────────────────────┤
│  catbase   (基础类型：transform、camera、cgltf、yaml)      │
│  free/scl  (基础库：容器、数学、IO、线程、log)               │
│  free/*    (第三方：glm、imgui、libpng、rapidyaml、vulkan…) │
└─────────────────────────────────────────────────────┘
```

依赖方向**严格自上而下**，下层不依赖上层；同层之间 `cat` 通过 `IRender` 抽象与 `catvulkan` 交互，不直接 include Vulkan 头文件。

## 4. 主要数据流

### 4.1 资源加载（glTF → 引擎）

```
*.gltf ──cgltf_parse──► cgltf_data
                          │
            Scene::load(cgltf_scene)
                          │
            Object::loadNode(cgltf_node)   // 递归子节点
              ├── Mesh::load(cgltf_mesh)
              │     └── Primitive::load(cgltf_primitive)
              │           ├── IRender::createVertexBuffer / IndexBuffer
              │           ├── Material::load(cgltf_material)
              │           │     └── IRender::createTexture（PNG/KTX/JPG）
              │           └── ShaderCache::getShader(vs, fs, primitive, joints)
              └── Object::loadSkin(cgltf_node)   // 关联 Joints
```

`Env` 负责贯穿整个加载过程：缓存纹理、缓存 Shader、维护 `cgltf_node*` → `Object*` 映射，避免重复创建与跨节点查找。

### 4.2 单帧渲染

```
Client::run
  └─ VulkanRender::beginDraw
      ├─ Pick Pass（可选）   beginPickPass → Scene::draw(isPick=true) → endPickPass(x,y)
      └─ Scene Pass         beginScenePass → Scene::draw(mvp, false, render) → endScenePass
            └─ Object::draw → Mesh::draw → Primitive::draw
                                              └─ IRender::draw2(...)
      └─ ImGui Pass         drawIMGUI(ImGui::GetDrawData())
  └─ VulkanRender::swap     // submit + present
```

每个 `Primitive::draw` 调用 `IRender::draw2`，由 `VulkanRender` 完成：根据 `PipelineKey` 查管线缓存、根据 `DescriptorDataKey` 查描述符集缓存，未命中则即时创建。

### 4.3 拾取（Pick Pass）

使用「颜色编码 ID」方案：
1. `Env::registerPickPrimitive(primitive)` 为每个待拾取 `Primitive` 分配唯一颜色（写入 push constant）。
2. Pick Pass 渲染到独立的 `RenderTarget`（`m_pickRenderTarget`）。
3. `endPickPass(x, y)` 把目标像素拷回 CPU，反查 `Primitive*`。

## 5. 关键约定

- **命名空间**：引擎所有代码位于 `namespace cat`；基础库位于 `namespace scl`；编辑器配置位于 `namespace game`。
- **内存策略**：使用裸指针 + 显式 `delete`，配合 `safe_delete` 宏（见 `catbase/cat/def.h`）。`scl` 容器是默认选择，禁止直接使用 STL 容器穿越接口。
- **接口隔离**：上层只与 `cat::IRender` 通信；Vulkan 句柄 (`VkXxx`) 不暴露给 `cat` 模块；`void*` 在 `IRender` 中代表设备资源句柄。
- **跨平台**：通过 `scl/type.h` 的 `SCL_WIN / SCL_APPLE / SCL_ANDROID` 宏区分；当前主线为 Windows + Vulkan。
- **Shader 路径**：`SHADER_PATH` 由 `TEST_VULKAN` 决定，分别指向 `shader/vulkan/` 或 `shader/opengles/`。

## 6. 构建与运行

- 入口 CMake：`testCat/CMakeLists.txt`，它 `add_subdirectory` 串起所有内部模块和第三方库。
- 构建产物路径：每个静态库输出到自身的 `lib64/`，可执行文件输出到 `testCat/bin64/`。
- 链接库（Debug/Release 分离）在 `testCat/CMakeLists.txt` 显式列出，便于审视依赖。
