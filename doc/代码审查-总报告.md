# cat 项目代码审查 — 总报告

> 审查日期：2026-05-30
> 审查范围：cat / catbase / catui / catvulkan / catwindows 全部非第三方源文件（95 个 .cpp/.h/.c/.inl，约 820KB）+ testCat 下 10 个 GLSL/Vulkan GLSL shader
> 审查方式：Multi-agent code review（6 个专家子 agent 分维度并行审查 + 增量保存）

## 项目概览（主 Agent 一致性检查）

- 项目名 `cat`，**独立 C++ Vulkan/GLES 自研渲染引擎**，不是 Unreal Engine。
- 命名空间 `cat::`，使用自研 STL `scl::`（`scl::varray`、`scl::array`、`scl::matrix`、`scl::vector3`、`scl::quaternion`），字符串 `cat::String`。
- 后端：Vulkan（`catvulkan/`）+ OpenGL ES 3.x（`shader_gles`、`gltf_raw_render`）。
- 窗口：Win32 + EGL。
- 资产：cgltf 加载 GLTF，ImGui + ImGuizmo 做 UI，xxhash 哈希。
- 渲染：前向，`Scene::draw` → `World::draw` → `Object::draw` → `Mesh::draw` → `Primitive::draw`。

**结论**：6 个维度审查独立完成，发现的问题在多个维度上交叉呼应（如 `Object::skinRoot()` 无限递归同时被逻辑、规范、崩溃安全三个维度独立发现），说明问题真实且高优先级。

## Critical 跨维度汇总（必须立即修复）

下面是被 **2 个以上维度** 同时标记或单独维度评为 Critical 的核心问题，按修复优先级排序。

### 必崩 / UB 类（当天必修）

1. **`cat/object.h:77` `Object::skinRoot() const` 无限自递归**
   `const Object* skinRoot() const { return skinRoot(); }` — const 版调用自身的 const 版 → 栈溢出。任何走到 const path 的代码立刻崩。
   - 被维度发现：崩溃、逻辑、规范（3 维交叉）
   - 修复：`return const_cast<Object*>(this)->skinRoot();`

2. **`cat/skin.h:24` `Skin::root() const` 同样无限自递归**
   - 被维度发现：崩溃、逻辑、规范、性能（4 维交叉）
   - 修复：同上。

3. **`cat/shaderMacro.cpp:72-81` `ShaderMacroArray::assign(const ShaderMacro*, int)` 变量名拼错**
   `clear()` 后循环 `add(m_macros[i])` —— 实际应为 `macros[i]`。清空后从空数组读越界，且产生空的 macro 数组。Shader permutation 全错。
   - 被维度发现：崩溃、规范、Shader、性能（4 维交叉）
   - 修复：把 `m_macros[i]` 改为 `macros[i]`。

4. **`catvulkan/cat/vulkanRender.cpp:287, 351` `delete (void*)`**
   `releaseVertexBuffer` / `releaseIndexBuffer` 末尾对 `void*` 直接 `delete`，**C++ 未定义行为**。每次 Primitive 析构都触发。
   - 被维度发现：崩溃、规范
   - 修复：`delete static_cast<svkBuffer*>(buffer);`

5. **`cat/shader.cpp:54-57` `_loadfile` 失败返回 `false`，函数返回类型是 `char*`**
   `false` 隐式转 NULL，调用方不检查 NULL 直接传给 `render->createShader(NULL, NULL)` → Vulkan/GLES 段错误。
   - 被维度发现：崩溃、逻辑、Shader（3 维交叉）
   - 修复：明确 `return NULL;`，调用方判空。

6. **`cat/shader.cpp:75-82` `_loadfile` macro 注入算法错误**
   找 `#version` 行后 `scl::strncpy_unsafe(buf, version, versionlen)` 把 `#version ... \n` 拷到 buf 开头，但 buf 开头 `[0, macrolen)` 是 0；产生 `#version` + 一堆 `\0` + macros + 原文 → GLSL 编译失败。
   - 被维度发现：崩溃、Shader（2 维交叉）
   - 这是 `default_30.vert/frag` 不能用的根因。
   - 修复：用 `String` 拼接代替 in-place 内存覆盖。

7. **`cat/shader.cpp:78-79` `while (*p++ != '\n')` 缺边界检查**
   如果 shader 文件最后一行是 `#version ...` 且无换行，`while` 一直 `*p++` 走出 buffer 边界 → 非法内存读。
   - 被维度发现：崩溃
   - 修复：`while (p < buf + buflen && *p != '\n') p++;`

8. **`catvulkan/cat/simplevulkan.cpp:2367-2386` `svkCopyImageToData` dataSize 计算顺序错**
   `int dataSize = memReq.size;` 写在 `vkGetImageMemoryRequirements` **之前**，dataSize 永远 0。pick / 截图 / image readback 全部静默拷贝 0 字节。
   - 被维度发现：崩溃
   - 修复：调换顺序。

9. **`cat/terrain.cpp:72` `setIndices(m_indices, 3, ...)` 硬编码 3**
   本应是 `INDEX_COUNT`，导致 terrain 只画一个三角形。
   - 被维度发现：崩溃、逻辑
   - 修复：用 `INDEX_COUNT`。

10. **`catvulkan/cat/vulkanRender.cpp ~VulkanRender` 没 `vkDeviceWaitIdle` 也没 `m_isInit` 检查**
    退出时直接 destroy GPU 仍在使用的资源（pipeline/buffer/image），Vulkan UAF；init 失败后析构会解引用未初始化指针。
    - 被维度发现：崩溃
    - 修复：析构入口 `vkDeviceWaitIdle(device)`；按 `m_isInit` 守护。

11. **`catbase/cat/cgltf_util.c:4-8` 链式三层解引用全无判空**
    `accessor->buffer_view->buffer->data` 任一层 NULL（不规范 GLTF / 外置 .bin 缺失）即崩。多处调用方依赖此函数。
    - 被维度发现：崩溃、逻辑
    - 修复：逐层判空。

12. **`cat/object.cpp:323-328` `releaseObjectIDMap()` 删除单例不置 NULL**
    再次调用即 double free；release 后再有 Object 析构会重新 new 空 map，逻辑错乱。
    - 被维度发现：崩溃
    - 修复：`delete s_objectIDMap; s_objectIDMap = nullptr;`

13. **`cat/object.cpp:52-58` `~Object` 不通知父对象**
    delete child 后 parent 的 `m_childs` 留悬垂指针，下次 `Object::draw` 解引用崩。
    - 被维度发现：崩溃
    - 修复：`if (m_parent) m_parent->_removeChild(this);`

### 跨平台编译失败类（Clang/iOS/macOS/Linux 必爆）

14. **`catwindows/cat/win32Window.cpp` include 大小写不匹配**
    - `cat/win32Window.cpp:7` `#include "cat/win32Window.h"` 大写 W vs 实际文件 `cat/win32window.h` 小写 w。Windows NTFS 不区分，Linux/macOS 区分 → 编译失败。
    - `cat/primitive.cpp:1` `#include "cat/Primitive.h"` 大写 P 同样问题。
    - `cat/skin.cpp:11` `#include "cgltf\cgltf.h"` 反斜杠。
    - 被维度发现：跨平台、规范
    - 修复：统一文件名 + include 路径大小写；反斜杠改正斜杠。

15. **`catbase/cat/camera.cpp:12-26` 构造函数初始化列表顺序与成员声明顺序不一致**
    MSVC 至多 `C4351` warning，**Clang `-Wreorder` 通常作为 error**。
    - 被维度发现：跨平台、逻辑
    - 修复：按声明顺序重排初始化列表。

### 性能必修类（每帧热路径浪费）

16. **`Object::globalMatrix()` + `Skin::generateJointMatrix()` 无缓存 O(N·D) + O(joints·depth)**
    场景层级 N、平均深度 D；50 joint × 深度 5 = 至少 250 次 mat4×mat4 / 每帧。
    - 被维度发现：性能
    - 修复：Transform / Object 加 dirty flag，每帧后序遍历预算缓存；`Object::draw` 把 `parentGlobal` 传递；joint matrix 直接读缓存。

17. **`Primitive::boundingBox()` 触发 GPU readback**
    `m_render->readVertexBuffer` 是 Vulkan map+memcpy，Vulkan 需等帧完成。若 culling/pick/选中显示在每帧调用 → GPU stall 灾难。
    - 被维度发现：性能
    - 修复：加载阶段 CPU 端算并缓存 `Box`，运行时直接返回。

18. **`Scene::draw` 平铺遍历，无视锥剔除**
    移动端 1080p/60fps 必须有 culling。
    - 被维度发现：性能
    - 修复：`Object::draw` 顶部用 cached boundingBox vs frustum 平面剔除。

19. **`AnimationChannel::apply` 每帧走 `ObjectIDMap` 查表**
    每帧每 channel 一次哈希查询，大场景几百次。
    - 被维度发现：性能、崩溃
    - 修复：`load()` 阶段缓存 `Object*` 指针。

20. **`VulkanRender::init` uniform buffer 48MB 常驻 host-visible**
    公式 `MAX_OBJECT × MAX_MATRIX × align`，实际单帧 < 1MB。
    - 被维度发现：性能
    - 修复：重算 buffer 大小，按帧动态扩容。

### Shader 必修

21. **`default.vert` vs `default_30.vert` 顶点 attribute layout 冲突**
    location 1 一个是 normal、一个是 color，C++ VAO 绑定到错的 shader 即错几何。
    - 被维度发现：Shader
    - 修复：统一 attribute layout 约定，加 `#define` 切换。

22. **`shaderc_compile_into_spv` 无优化、无 SPIR-V disk cache**
    移动端冷启动每次都重编译。
    - 被维度发现：Shader、性能
    - 修复：编译期/首启动缓存 SPIR-V 到磁盘。

23. **`shader_gles.cpp` 注释掉 `glBindAttribLocation`**
    ES 1.00 路径下 `default10.vert` 不支持 `layout(location=...)`，依赖 bind attrib 才能正确绑定 VBO。
    - 被维度发现：Shader
    - 修复：恢复 `glBindAttribLocation`。

24. **`ShaderCache::getDefaultShader` 硬编码 `SHADER_PATH "object.vert"`，GLES 目录无此文件**
    GLES build 启动崩溃。
    - 被维度发现：Shader、崩溃、规范
    - 修复：按后端区分默认 shader 名。

## 系统性问题（架构层面）

### 1. 指针生命周期没有 ownership 模型
- 父子 `Object` 之间是 raw pointer，删一个 child 不会通知 parent；
- `shader cache` / `material` / `texture` 之间循环引用且 ownership 不明；
- `Light` 没有析构函数，`m_transform` 永久泄漏；
- `Primitive` 的 `m_shader`/`m_pickShader` 是借用 cache 的 raw pointer，cache 先析构即悬垂。

**建议**：引入弱引用、明确 ownership 注释或简单的引用计数。

### 2. 静态 / 全局对象退出顺序未定义
- `Object::s_objectIDMap` 是 `new` 出来的全局指针，`releaseObjectIDMap` 后不置 NULL；
- `TextureFile::empty()` Meyer's singleton；
- `cat::names` 全局对象在 main 之前构造；
- `shaderCache` 与 `IRender` 析构顺序未约束。

**建议**：所有跨"main"边界的全局/静态用 explicit init/shutdown 接口管理，禁用隐式析构链。

### 3. 多线程语义未明确
`ObjectIDMap`、`scl::hash_table`、Vulkan resource cache 都没锁。若声明仅主线程使用，则需文档化并加 `assert(IsMainThread())` 守护；否则需要补锁/原子。Vulkan 资源池（descriptor / command）特别需要 thread-affinity。

### 4. 错误处理偏向 `assert`，release 下静默失效
`assert(false)` 占了大多数失败分支，release build 下：
- gltf 加载失败继续走，产生 garbage 数据；
- shader 加载失败 NULL 沿着调用链传到 Vulkan/GLES，必崩；
- 数组越界 / 索引非法时 release 不报。

**建议**：关键失败路径改 `abort()` + 项目自有日志；非关键路径明确 fallback。

### 5. `void*` 接口削弱类型安全
`IRender` 的 buffer/texture/shader 句柄全是 `void*`，导致 `delete void*`（UB）、`reinterpret_cast<GLuint>(void*)` 截断、参数错位编译器查不出。
**建议**：定义 opaque handle 类型（`struct BufferHandle { void* p; };`）即可获得编译期类型检查。

### 6. 文件命名 / include 大小写完全不一致
- `win32Window.cpp` ↔ `win32window.h`（W 大小写不同）
- `cat/Primitive.h`（错误大写） vs 实际 `primitive.h`
- `DescriptorDataKey` vs `descriptorAllocator`（同目录大小写风格混乱）
- `gltf_raw_render` vs `gltfLoader`（同目录 snake_case vs camelCase）
**建议**：统一为 camelCase，include 路径全小写。CI 加 case-sensitive lint。

### 7. 大量死代码 / 废弃文件
- `.txt` 后缀的废弃源（`uiRenderOpenGL.h.txt`、`resources.h.txt`、`old_object_cpp.txt`、`load_png.cpp.txt` 等）
- `shader_gles.h` 内 ~120 行注释代码
- `IRender.h` 内 ~130 行注释代码
- `Object::save` 函数体几乎全注释，只剩 `name`/`id` 两字段
- `gltfLoader.h/cpp`、`grid.cpp`、`skybox.cpp` 是空壳

**建议**：直接 `git rm`，git 历史保留即可。

### 8. union 误用 = UB
`AnimationChannel`、`KeyFrame` 都把 `quaternion`、`vector3`、`vector3` 放进 union，构造时**连续调三个 `clear()`**，只有最后一个的成员是 active，前两个写非活跃成员是 C++ UB。当前因 quaternion/vector3 都是 trivially copyable 没崩，MSVC 优化级别提高或换 Clang 可能爆。
**建议**：union 改 `struct`（多 32 字节内存换正确性），或改 `std::variant`（C++17）。

## 整体评价

- **总体评估**：⚠️ **有风险，需要修改**
- **关键问题**：
  - 至少 **8 个必崩级 Critical** 在主要代码路径上潜伏（const 无限递归、shader load NULL、Vulkan UAF、`delete void*` 等）
  - **跨平台编译**未跨过 Linux/macOS（include 大小写、`-Wreorder` 等）
  - **渲染热路径**缺基础优化（无视锥剔除、矩阵无缓存、shader cache 字符串拼 key、48MB uniform buffer）
- **结论**：❌ **当前状态不建议合入主干 / 发布**。
  - **当天必修**：上面 #1~#13 共 13 项；
  - **本周内修**：#14~#24 共 11 项 + 所有 Vulkan 资源生命周期同步问题；
  - **本月内修**：约 190 项 Warning + 145 项 Suggestion，可以批量按维度分阶段处理。
- **正面评估**：
  - 项目结构清晰，模块化合理（base / ui / vulkan / windows 分层）；
  - 数学库 `scl` 设计独立可测；
  - shader cache + macro permutation 是合适的渲染架构；
  - 大多数问题是工程实现细节，没有架构性死结。
