# 子系统 — 第三方依赖（free/）

> 上级：[架构总览](./架构总览.md)

`free/` 目录集中所有第三方源码（包括"内部基础库" `scl`，它在仓库里和外部库放在一起，但属于自有代码）。所有依赖都以**源码 + CMake 子项目**形式接入，构建期产物落到各自的 `lib64/`，由 `testCat/CMakeLists.txt` 显式链接。

## 1. 依赖一览

| 库 | 位置 | 引擎角色 |
|----|------|----------|
| `scl` | `free/scl/` | 内部基础库（容器/数学/IO/线程/log）—— 实际是项目自有代码 |
| `glm` | `free/glm/` | 备用线性代数库（主流程使用 `scl` 的 matrix/vector，glm 用于个别 shader 工具与对照） |
| `imgui` | `free/imgui/` | UI 框架（编辑器） |
| `rapidyaml` | `free/rapidyaml/` | YAML 解析（场景与配置的持久化） |
| `cgltf` | `catbase/cat/cgltf.c` + 头依赖 `free/cgltf/` | glTF 2.0 加载（单文件库，源码直接编进 `catbase`） |
| `libimg` `libpng` `libtga` `jpeg_turbo` `libktx` | `free/libxxx/` | 纹理解码：PNG / TGA / JPEG / KTX；`libimg` 是统一入口 |
| `zlib` | `free/zlib/` | PNG/KTX 等的压缩依赖 |
| `vulkan` | `free/vulkan/` | Vulkan Loader 头与导入库 |
| `shaderc` | `free/lib64/shaderc_combined*.lib` | GLSL → SPIR-V 运行期编译 |
| `spirv_cross` | `free/spirv_cross/` | SPIR-V 反射，提取 descriptor set 布局与 push constant range |
| `gles/qualcomm` | `free/gles/qualcomm/` | OpenGL ES 头与桥接 lib（仅 GLES 路径需要，主线 Vulkan 不再使用） |

## 2. scl —— 内部基础库

`scl` 体量最大、与引擎耦合最深，单独详细介绍。`namespace scl`，全部头文件位于 `free/scl/`，编译为静态库 `scl.lib`。

### 2.1 容器与算法

| 头文件 | 用途 |
|--------|------|
| `varray.h` | 动态数组（类似 `std::vector`，但 POD 优化、可关闭析构） |
| `array.h` | 固定容量数组（栈上） |
| `vector.h` | 数学向量（`vector2 / vector3 / vector4 / vector2i`）—— 不要与上面的 `varray` 混淆 |
| `matrix.h` | 4×4 矩阵 + `z_range` 枚举（OpenGL/Vulkan NDC） |
| `quaternion.h` | 四元数 + 与欧拉角互转 |
| `math.h`、`plane.h`、`rect.h`、`point.h` | 杂项数学 |
| `hash_table.h` | 闭散列哈希表（容量 + MAX_CONFLICT 预分配） |
| `tree.h` | 平衡二叉树（按 key 查找） |
| `list.h`、`stack.h`、`heap.h` | 链表、栈、堆 |
| `pool.h`、`alloc_pool.h`、`page_array.h` | 对象池、分页池 |
| `ring_buffer.h`、`ring_queue.h`、`vring_queue.h` | 环形缓冲/队列 |
| `bitset.h`、`vbitset.h`、`bitdef.h` | 位集合 |
| `big_int.h`、`zip_int.h` | 大整数 / 压缩整数 |
| `string.h`、`stringdef.h`、`encoding.h` | 字符串与编码 |

### 2.2 IO 与文件

`file.h / file_mapping.h / file_reader.h / directory.h / path.h / ini_file.h`，加上 `dump.h`（二进制 dump 辅助）。这些 API 都不抛异常，错误通过返回值传递。

### 2.3 线程与同步

`thread.h`（线程本体）、`task_thread.h`、`task_thread_pool.h`（任务式调度）、`thread_allocator.h`、`allocator_thread.h`（thread-local 分配器）、`memory_barrier.h`、`frame_lock.h`（按帧定速器）、`thread_log.h`。

### 2.4 日志与诊断

`log.h / log_file.h / log_define.h`：分级日志（VERBOSE / DEBUG / INFO / WARN / ERROR / FATAL + USER1）；流式接口 `log_info_safe << ...`，文件 + 控制台双路。`assert.h / backtrace.h`：断言与堆栈。

### 2.5 通用工具

`type.h`（平台宏 + `uint / byte / int8/16/32/64` 基础类型 + `type_id<T>()`）、`type_traits.h`、`ptr.h`（智能指针包装）、`function.h`（`class_function<>` 仿函数）、`time.h`、`pair.h`。

### 2.6 平台桥

`android.h/.cpp`：Android 启动辅助。Apple 平台通过 `*.xcodeproj`（在 `free/scl/` 内）单独参与构建。Windows 走顶级 CMake 即可。

## 3. 主线第三方库

### 3.1 glm

只用了一小部分头（`free/glm/`），主要在做矩阵插值 / shader 调试时与 `scl::matrix` 对照。引擎接口一律使用 `scl` 类型，glm 不外泄到模块边界。

### 3.2 imgui

`free/imgui/`：标准 Dear ImGui 源码 + tables 扩展。两个 backend 各自归位：

- 平台 backend `imgui_impl_win32` 放在 `catwindows`；
- 渲染 backend `imgui_impl_vulkan` 放在 `catvulkan`；
- 业务侧的封装控件在 `catui/imguiex`。

### 3.3 rapidyaml

`free/rapidyaml/` 是 ryml + c4 基础库 + 子模块 `debugbreak / fast_float`。`catbase/cat/yaml.h` 在它之上提供简化包装：上层只用 `yaml::document / yaml::node`，不直接接触 `c4::yml::Tree`。

### 3.4 cgltf

cgltf 是单文件 C 库。仓库选择直接把 `cgltf.c` 放到 `catbase/cat/` 内编译，避免独立子项目；公开头通过 `cgltf_util.h` 包装并补充 accessor helpers。

### 3.5 图像解码栈

| 库 | 角色 |
|----|------|
| `libpng` | PNG，需要 `zlib` |
| `libtga` | TGA |
| `jpeg_turbo` | JPEG |
| `libktx` | KTX / KTX2（含压缩纹理） |
| `libimg` | 引擎自封的统一入口；按扩展名分派到上面四者 |

`IRender::loadImage(filename, ...)` 和 `IRender::createTexture(filename, ...)` 内部都通过 `libimg` 落地实现。

### 3.6 Vulkan SDK 部分

- `free/vulkan/Include/`：Vulkan API 头；
- `free/vulkan/Lib64/vulkan-1.lib`：Loader 导入库；
- `free/lib64/shaderc_combined.lib`：GLSL → SPIR-V 运行期编译器（在 `svkDevice::shaderCompiler` 中持有）；
- `free/spirv_cross/`：SPIR-V 反射，用于生成 `svkShaderProgram::descriptorSetLayoutBinds / pushConstRanges`。

这三件构成了"运行期 shader 流水线"：源码 → SPIR-V → 反射 → DescriptorSetLayout + Pipeline。

### 3.7 zlib

被 libpng / libktx 等依赖，本身不直接被引擎使用。`testCat` 显式链接它以满足传递依赖。

### 3.8 gles/qualcomm

只在 GLES 路径需要：包含 EGL/GLESv2 头与 Qualcomm 桥接 lib。当前主线 (`TEST_VULKAN` 开启) 已不再使用，但仍随 `testCat` 链接（这是历史遗留，可以在后续整理中移除）。

## 4. 构建顺序与依赖图

`testCat/CMakeLists.txt` 的 `add_subdirectory` 顺序基本反映了底→顶的依赖：

```
scl → catbase → catui → catwindows → libimg/jpeg/png/tga/ktx/zlib → imgui
  → spirv_cross → cat → catvulkan → rapidyaml → glm → testCat
```

`testCat` 通过 `add_dependencies(...)` 保证全部库先于自身构建；链接时 Debug/Release 各自一份 `_d` 后缀，避免混链。
