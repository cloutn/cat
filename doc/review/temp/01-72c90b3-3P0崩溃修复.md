## Warning
- [崩溃 / 跨平台编译] `catvulkan/cat/pipelineKey.cpp:21-37` — `memset(this, 0, sizeof(*this))` 当前是安全的（`PipelineKey` 无虚函数、无基类，仅 4 个 POD 成员，参见 `pipelineKey.h:7-22`），但**没有任何护栏阻止后续有人给 `PipelineKey` 加虚函数 / 派生**，一旦加了虚函数 vtable 指针会被 `memset` 清零，触发 vcall 即崩。建议在 cpp 内补一行编译期防呆：
  - `static_assert(std::is_trivially_copyable<PipelineKey>::value, "PipelineKey must stay POD; memset(this) will destroy vtable otherwise");`
  - 或更直接的 `static_assert(!std::is_polymorphic<PipelineKey>::value, ...)`。
  - 上下文：cpp 里已经有"TODO 加 static_assert(sizeof(PipelineKey)) 提醒同步 hash/eq"，这条 POD assert 与 sizeof assert 可并入同一块加上。
- [崩溃 / 逻辑] `cat/env.cpp:118-124 registerPickPrimitive` — 从 `scl::array<T, 1024>` 改为 `scl::varray<T>` 后，**上限从 1024 提升到 (近似)无限**，配合 `argb_to_float / float_to_argb`（id 用 ARGB 4 通道编码）理论容量是 `2^32`，但其编码经过 float 往返：
  - `id >= 16777216 (2^24)` 时 float 尾数 23 位无法表示，往返必失真 → `getPickPrimitive` 取到错主或越界；
  - alpha 通道若被 framebuffer blending 改写，回读 id 也会偏。
  - 这是**预先存在**的逻辑缺陷，不是这次 diff 引入；但 1024 上限被"自动扩容"掩盖以后，长跑 / 大场景下**第一个会被踩到的不是 OOM，而是 pick 拾取到错对象**——属于"修了崩溃但放大了上游 bug 被触发的概率"，建议本 commit 后紧跟一个补丁：在 `registerPickPrimitive` 入口 `assert(m_pickPrimitives.size() < (1 << 24));`，把隐性失真转成显性 assert。
- [规范] `cat/env.h:59-61` 新增的中文注释解释了 `varray` 的取舍，是好实践；但顶部 `cat/env.h:1` **缺 `#pragma once`**（该文件首行为空、第二行直接 `#include`）。AGENTS.md 明确要求所有头文件 `#pragma once`，这是**预先存在的违规**，不是本 diff 引入，但既然本次也改动了 env.h 的 include 区，顺手补一行 `#pragma once` 成本极低、收益是封死潜在的重复定义。请确认作者是否有意保留（极少数情况下用 include guard 替代，但本文件也没有 ifndef 守卫）。
