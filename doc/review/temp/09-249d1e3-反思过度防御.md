### 2.1 `delete void*` 修复（P0，正确）

```diff
-svkDestroyBuffer(m_device, *static_cast<svkBuffer*>(vertexBuffer));
-delete vertexBuffer;
+svkBuffer* buf = static_cast<svkBuffer*>(vertexBuffer);
+svkDestroyBuffer(m_device, *buf);
+safe_delete(buf);
```

- `delete void*` 是 [expr.delete]/3 明确 UB（不会调用 dtor、size 信息丢失）；先 `static_cast<svkBuffer*>` 再 `safe_delete` 走的是有类型 path → ✓ 完全消解 UB。
- `safe_delete` 宏对类型确定的指针展开为 `delete` + 置 NULL，符合 cat 风格 §1.4 的"一律走 `safe_delete`"约定。
- `releaseIndexBuffer` 同形修复，对称。
- 顺序：`svkDestroyBuffer` 先释放 device 侧资源、再 `delete` host 侧 svkBuffer 元数据；与 `m_device.device` 仍 valid 的前提一致 → ✓。

### 2.2 `endScenePass` 越界 + `_createMainRenderTarget` 复位（P0，正确）

- 调用链复核：
  - `VulkanRender` ctor `m_prevFrameIndex(-1)`（`vulkanRender.cpp:55`）。
  - `init()` 内调 `_createMainRenderTarget` → `m_frameIndex = 0; m_prevFrameIndex = 0;`（line 1050–1052）→ 进入合法范围。
  - `beginDraw` 入口 `m_prevFrameIndex = m_frameIndex;`（line 573）→ 保证下一次 endScenePass 用到的 prev 永远是上一次合法 frameIndex。
  - `endScenePass` 入口 `assert(m_prevFrameIndex >= 0 && m_prevFrameIndex < m_frameCount);`（line 725）→ 不变量哨兵。
- 反思文档 §对应反思条目断言"必须先 beginDraw 才能进入 endScenePass" —— 与代码注释一致 → ✓。
- `recreateSwapchain` 路径：`_createMainRenderTarget` 重新跑 → `m_prevFrameIndex` 复位 0；同 commit 一并修复"recreate 后保留旧 swapchain 索引导致 endScenePass 拿未 signal semaphore"的潜在死等。
- **唯一遗留点**：commit message 没说为什么不用 `m_prevFrameIndex = -1` 而是 `= 0`。`-1` 配合 `endScenePass` assert 也能 fail-loud（首帧若漏调 beginDraw 立刻断言挂掉），但 `0` 让首帧也走"prev = 0"，行为更"不犯错优先"。当前选择是正确的——`assert` 防的是"控制流错乱"，`0` 防的是"recreate 后第一帧"。两者并不冲突。
