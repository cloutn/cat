## Warning

### W1. `simplevulkan.cpp` — `memReq.size` 截断到 `int`

```cpp
int dataSize = static_cast<int>(memReq.size);   // memReq.size 是 VkDeviceSize（uint64）
```

- `VkDeviceSize` 是 `uint64_t`。窄化到 `int` 在大资源（>2 GiB，比如 BC1 16K×16K cubemap mip0 ≈ 1.3 GiB 不会爆，但 RT 链 / 大体积纹理链可能）会负数或截断。
- 后面 `if (dataSize > dataCapacity) dataSize = dataCapacity;` 也是 `int`，叠加一次窄化。
- 建议：`int` → `size_t` 或 `VkDeviceSize`，或在 cast 前 `assert(memReq.size <= INT_MAX)`。
- 触发概率：当前小项目用不到，但属于"埋点警告"，留 TODO 注释即可。

### W2. `simplevulkan.cpp` — `vkMapMemory` 失败后未跳过拷贝

```cpp
VkResult err = vkMapMemory(device.device, image.memory, 0, memReq.size, 0, &imageData);
assert(!err);                       // ← Debug 才挂；Release 继续往下走
if (dataSize > dataCapacity) ...
memcpy(data, imageData, dataSize);  // imageData 可能仍是 NULL
```

- `assert` 在 Release 被剥离，`imageData` 若为 NULL 后续 `memcpy` 直接段错误。
- 建议：`if (VK_SUCCESS != err) return 0;`（或与现有错误返回值一致）。
- 与本 commit 的"防 NULL/防崩溃"主题一致，建议补一刀。

### W3. `shader.cpp` — 失败路径静默，调用者拿不到信号

```cpp
if (NULL != vs_code && NULL != ps_code)
    m_deviceShader = render->createShader(vs_code, ps_code);
delete[] vs_code;
delete[] ps_code;
```

- 防崩溃修复正确（`delete[] NULL` C++ 标准合法）。
- 但 `m_deviceShader` 保持上次值（构造时若是 NULL 则 NULL，重载时则是旧 handle），调用方无法区分"加载成功"和"加载失败"。
- 建议：失败时 `m_deviceShader = NULL;`（若是重载场景）+ 一行 `scl::log` 报错。否则 GPU 端"用旧 shader"或"画不出来"会让排查变难。

### W4. `shader.cpp::_loadfile` — `return NULL` 与"返回 char\*"语义对齐 OK

- `return false` → `return NULL`：类型修复正确。
- 但 `_loadfile` 本身签名应该是 `char*`，`assert(false)` + `return NULL` 在 Release 下 `assert` 失效，仅靠 NULL 传播；此修复让 NULL 真正可被上层（W3 那个 if）拦截，与 shader.cpp 的修复构成正确闭环。
- 没有问题，仅备注：fopen 失败属预期可恢复错误，不应 `assert(false)` 这么强；可改为 `scl::log::error("shader file not found: %s", filename)`。归 Suggest。

- **死代码删除**：7 个 .txt 文件不参与编译，零编译影响；纯仓库整洁度收益。
