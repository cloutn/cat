# 阶段08-主线复核与归并

## 复核方式

- 只做静态审查、diff 审查和当前最终代码状态抽查。
- 不运行 build / 编译。
- 对子审查结果做去重与行号校正；最终报告优先列仍能在当前代码中复现的风险。

## 主线确认的高优先级问题

1. `99ac00f` 的 shader reload 失败路径仍会保留已释放的 `m_deviceShader`，当前代码 `cat/shader.cpp:31-49` 可复现。
2. `3df3ecb` 的 `_loadSkin` 对 unmapped joint 使用 `continue`，会压缩 joint 数组，破坏 glTF `JOINTS_0` 下标与 IBM 的一一对应。
3. `2049f99` 的 `_loadAnimChannel` 没有按 target path 校验 output type，rotation + vec3 会在 Release 读 `f[3]` 越界。
4. `99ac00f` 之后 `cgltf_get_accessor_buffer()` 可返回 `NULL`，但 `cat/gltfLoader.cpp:252` 和 `cat/gltfLoader.cpp:537-543` 的 index / vertex 读取路径没有 fail closed。
5. `7ba65a6` 的 texture 文件缺失修复只挡住 `fopen(NULL)`，但 `svkCreateTexture()` 后续仍对 null image 做 layout transition / image view 创建。
6. `7353b3b` / `7ba65a6` 的 acquire-recreate 重试路径仍可能让 acquire signal 的 semaphore 与 submit wait 的 semaphore 不一致。
7. `7353b3b` 的 `recreateSurface()` 在 minimized 分支返回前没有把已销毁的 swapchain / render target owner 句柄清零。
8. `e7010b8` 只在 `~VulkanRender` waitIdle，`Client::~Client` 释放 scene/env 期间的 texture / buffer / shader 仍可能早于 GPU idle。
9. `aebb381` 的 `build_jolt()` 把 `"-A x64"` 作为单个 argv 传给 CMake，且 `exec_cmd()` 吞掉失败，新环境可能误以为构建成功。

## 调整后的严重度

- `releaseObjectIDMap` release 后复活：当前 shutdown 顺序有注释约束，主线归为 Warning，而不是 Critical。
- `Primitive::release()` 非幂等：public API + 析构二次调用风险成立，归为 Warning。
- `KeyFrame` / `AnimationChannel` union 活跃成员问题：`clear(MOVE/SCALE)` 对 inactive union member 调成员函数，主线补充为 Warning。
- 文档命名 / 编码 / ignore 策略：保留为 Warning / Suggestion，不进入运行时 Critical。
