## Critical

### C1 shader reload 失败后保留已释放的 m_deviceShader

- commit：`99ac00f`
- 文件：`cat/shader.cpp:31-49`，`cat/shader.cpp:132-138`
- 风险：`Shader::shader()` 在 dirty reload 时先 `releaseShader(m_deviceShader)`，然后才 `_loadfile()`。如果任一 shader 文件加载失败，`m_deviceShader` 仍是已释放指针，且 `m_dirty=false`。下一帧 draw 会使用悬垂 `svkShaderProgram*`，析构还可能二次释放。
- 建议：先把源码加载和 `createShader()` 放到局部 `newDeviceShader`；成功后再释放旧 shader 并 swap。失败时保留旧 shader，并保持 dirty 或记录失败状态。

### C2 Skin joint 被压缩导致 JOINTS_0 / IBM / 矩阵数组错配

- commit：`3df3ecb`
- 文件：`cat/gltfLoader.cpp:328-338`，`cat/skin.cpp:65-95`
- 风险：`_loadSkin()` 对未映射 joint 直接 `continue`，会压缩 `m_joints`。但 glTF 顶点 `JOINTS_0` 和 `inverseBindMatrices` 仍按原 `skin.joints` 下标对齐。中间缺一个 joint 后，后续矩阵全部错位，轻则蒙皮扭曲，重则 shader 读取未上传矩阵。
- 建议：不要压缩 joint 数组。保留原 jointCount 下标；任一 joint 缺失时禁用 Skin 或构造完整占位矩阵并 fail closed。

### C3 animation rotation channel 可用 vec3 触发 Release 越界读

- commit：`2049f99`
- 文件：`cat/gltfLoader.cpp:397-447`
- 风险：`_loadAnimChannel()` 只校验 output 是 `vec3` 或 `vec4`，没有按 target path 区分。rotation 如果是 `vec3`，Debug 下 assert，Release 下继续读 `f[3]` 越界。
- 建议：ROTATE 必须要求 `cgltf_type_vec4`；MOVE / SCALE 必须要求 `cgltf_type_vec3`；不匹配直接 `return false`。

### C4 cgltf accessor buffer 可为 NULL，但 index / vertex 路径继续 memcpy

- commit：`99ac00f`
- 文件：`cat/gltfLoader.cpp:252-253`，`cat/gltfLoader.cpp:537-543`，`cat/primitive.cpp:303-314`
- 风险：`cgltf_get_accessor_buffer()` 已改成可返回 `NULL`，但 primitive index 和 vertex flatten 路径没有同步判空。外部 `.bin` 缺失、buffer 未加载或 accessor 非法时，会把 NULL 传进 GPU buffer 创建或对 NULL 做指针偏移和 `memcpy`。
- 建议：每个 accessor buffer 取出后立即判空；任一 index / attr buffer 缺失时丢弃该 primitive 或让 glTF 加载失败返回。

### C5 texture 文件缺失后仍对 null image 做 Vulkan 操作

- commit：`7ba65a6`
- 文件：`catvulkan/cat/simplevulkan.cpp:250-267`，`catvulkan/cat/simplevulkan.cpp:1558-1573`
- 风险：`_createTextureImageFromFile()` 在 `fopen` 失败后只 `return`，但 `svkCreateTexture()` 后续仍执行 `_setImageLayout()` 和 `_createSamplerAndImageView()`。资源缺失从文件 IO 崩溃变成 Vulkan null image / null imageView 崩溃。
- 建议：让 `_createTextureImageFromFile()` 返回 bool；失败时 `svkCreateTexture()` 返回无效纹理并由上层 fail closed，或创建 1x1 fallback texture。

### C6 acquire 失败 recreate 后，signal / wait semaphore 可能错位

- commit：`7353b3b` / `7ba65a6`
- 文件：`catvulkan/cat/vulkanRender.cpp:573-574`，`catvulkan/cat/vulkanRender.cpp:743-748`，`catvulkan/cat/simplevulkan.cpp:2216-2234`
- 风险：`vkAcquireNextImageKHR` 失败后 callback 会 recreate swapchain，并重置 frame 状态；但 `svkAcquireNextImage()` 的局部 `frame` 仍是旧索引。重试 signal 的 semaphore 和 `endScenePass()` wait 的 semaphore 可能不是同一个，GPU submit 可死等。
- 建议：不要在 `svkAcquireNextImage()` 内部 callback 后隐式继续；返回 `VkResult + imageIndex + semaphoreIndex`，由 `beginDraw()` 统一重启当前帧。

### C7 recreateSurface minimized 返回后保留已销毁句柄

- commit：`7353b3b`
- 文件：`catvulkan/cat/vulkanRender.cpp:1055-1061`，`catvulkan/cat/vulkanRender.cpp:1314-1322`
- 风险：`recreateSurface()` 先销毁 main / pick render target，再创建新 surface；如果新 surface 尺寸为 0，直接 return。此时 swapchain、render pass、depth image、framebuffer 等 owner 成员仍可能保留已销毁句柄，后续析构或再次 recreate 会 double destroy / 使用 stale handle。
- 建议：所有 destroy helper 成功后清零 owner 成员，并重置 `m_frameCount/m_frameIndex/m_prevFrameIndex`；minimized return 前进入明确的“无 render target”状态。

### C8 场景资源释放早于 GPU idle，仍有 in-flight UAF 风险

- commit：`e7010b8` / `99ac00f`
- 文件：`testCat/client.cpp:156-168`，`catvulkan/cat/vulkanRender.cpp:455-461`，`catvulkan/cat/vulkanRender.cpp:563-566`
- 风险：`~VulkanRender` 里的 `waitIdle()` 只保护 render 自身析构；`Client::~Client` 先 delete scenes / terrain / env，期间会释放 texture / buffer / shader，而 `VulkanRender::release()` 是空函数。上一帧 GPU 若仍 in-flight，资源会早于 waitIdle 被销毁。
- 建议：`VulkanRender::release()` 至少执行 `waitIdle()`，并在 `Client::~Client` 释放场景资源前调用；长期方案是按 frame fence 延迟销毁资源。

### C9 build_jolt 的 CMake 参数和错误处理会制造“假成功”

- commit：`aebb381`
- 文件：`tool/script/setup.py:68`，`tool/script/mytool.py:39-42`，`testCat/CMakeLists.txt:129`、`:154`
- 风险：`G.arch_param` 在 VS 路径下是单个 argv `"-A x64"`，`subprocess.run(list)` 不会拆成 `"-A", "x64"`。CMake 失败后 `exec_cmd()` 只打印不抛异常，`build_jolt.bat` 仍会显示 complete，但 `testCat` 已硬链接 `free/lib64/jolt(_d).lib`，新环境可能到链接阶段才缺库。
- 建议：把 arch 参数改为 list 并展开；`exec_cmd()` 失败后重新抛异常；`build_jolt()` 末尾显式检查 `jolt.lib` / `jolt_d.lib` 是否存在。

## Warning

### W1 Object::addChild 不处理重挂和重复添加

- commit：`0698ba8`
- 文件：`cat/object.h:49`
- 风险：`addChild()` 直接改 `c->m_parent` 并 push。对象从旧 parent 重挂时，旧 parent 仍持有同一 child；重复 add 时当前 parent 也会持有重复指针。析构阶段可能重复 delete / UAF。
- 建议：先从旧 parent detach；若 child 已在当前 `m_childs` 中则直接返回。

### W2 releaseObjectIDMap 后仍可 lazy-new 空 map

- commit：`0698ba8` / `249d1e3`
- 文件：`cat/object.cpp:163-170`，`cat/object.cpp:276-279`
- 风险：`releaseObjectIDMap()` 后，后续 `objectByID()` 或 Object 析构仍会经 `_objectIDMap()` 重新创建空 map，导致 ID 查询失真和清理落到错误 map。当前 shutdown 顺序依赖注释约束，缺少运行时保护。
- 建议：增加 released 标志，release 后 `objectByID()` 返回 NULL；析构只在 map 存在时 del；最好统计 active Object，确保全部销毁后才 release。

### W3 Primitive::release 不是幂等

- commit：`bbbbaa1`
- 文件：`cat/primitive.cpp:130-162`
- 风险：`Primitive::release()` 是 public 且析构也会调用。当前 delete `m_deviceVertexBuffers` 后没有置 NULL，手动 release 后析构会再次 delete 同一数组。
- 建议：释放后设置 `m_deviceVertexBuffers = NULL`，并清零 `m_attrCount`；所有 release 路径都要可重复调用。

### W4 yaml::node 拷贝 document 但 NodeRef 仍引用原 Tree

- commit：`bbbbaa1`
- 文件：`catbase/cat/yaml.cpp:70-78`
- 风险：`node` 构造时复制了 `document`，但 `m_node` 仍可能引用原 `Tree`。node 逃出原 document 生命周期或 iterator 使用副本时，NodeRef 和 Tree owner 会错位。
- 建议：`node` 持有原 `document*` / shared owner；或复制后把 NodeRef 重新绑定到副本 Tree 的同 id 节点。

### W5 非 TEST_VULKAN 分支仍引用已注释成员

### W6 KeyFrame / AnimationChannel 的 union 活跃成员问题仍存在

- commit：`8e643f7`

- 风险：构造只初始化 `m_rotate` 后，`clear(MOVE/SCALE)` 和 `_resetTransform()` 会对 inactive union member 调成员函数。MOVE / SCALE 动画在“时间早于首帧”或 reset 路径上仍有 UB 风险。
- 建议：回到 struct 存储，或用显式 active type + placement new / destroy 管理 union 生命周期。

### W7 _loadIBM 忽略 accessor offset / count / stride

- commit：`3df3ecb` / `2049f99`
- 文件：`cat/gltfLoader.cpp:559-577`
- 风险：当前按 `buffer_view->offset` 和 `view->size` 直接 memcpy，忽略 `accessor->offset`、`accessor->count`、stride / sparse，并要求 view size 精确等于 jointCount 矩阵大小。合法共享 bufferView 会被误判无效或读错数据。
- 建议：用 cgltf accessor API 解包；至少校验 `accessor->count == jointCount`，按 `buffer_view->offset + accessor->offset` 和 stride 逐元素复制。

### W8 inverseBindMatrices 缺省值应为 identity

- commit：`3df3ecb`
- 文件：`cat/gltfLoader.cpp:315-320`
- 风险：glTF 的 `inverseBindMatrices` 是可选字段，缺省语义是 identity。当前缺失时直接让 skin unusable，可能启用 `SKIN` shader 但上传 0 个矩阵。
- 建议：字段缺失时生成 jointCount 个 identity IBM；字段存在但格式/数量非法时才禁用 Skin。

### W9 动画 accessor 假设紧密 float 排布

- commit：`2049f99`
- 文件：`cat/gltfLoader.cpp:410-430`
- 风险：`times[i]` 和 `frameDatas[i * componentCount]` 假设 accessor 紧密排列，未处理 stride / sparse。合法但非紧密数据会生成错误关键帧。
- 建议：使用 `cgltf_accessor_unpack_floats` / `cgltf_accessor_read_float`，或显式按 accessor stride 读取。

### W10 动画时间和 unsupported target path 仍未 fail closed

- commit：`2049f99`
- 文件：`cat/gltfLoader.cpp:421-450`
- 风险：`+Inf` 或超大正时间仍会进入 `static_cast<uint>(safeTime * 1000)`；glTF 合法的 `weights` target path 会落到 `KEY_FRAME_TYPE_INVALID`，但函数仍可能返回 true 并生成无效 channel。
- 建议：增加 finite / 上限检查；`_cgltfType2KeyFrameType()` 返回 INVALID 时直接 `return false`。

### W11 dynamic UBO descriptor range 和实际 buffer size 不匹配

- commit：`7353b3b`
- 文件：`catvulkan/cat/vulkanRender.cpp:790-814`，`catvulkan/cat/vulkanRender.cpp:931-946`
- 风险：descriptor range 固定为 `maxUniformBufferRange - 1`，但每帧 uniform buffer 按实际预算约 4.25MB。靠近 draw 上限时 `dynamicOffset + range` 可能越过 buffer size。预算失败也只是 `assert + return 0`，caller 仍继续 bind / draw。
- 建议：descriptor range 用实际 per-binding 大小；预算失败后 `draw2()` 立即返回，不再 bind descriptor / pipeline。

### W12 indexOffset 只 assert，Release 仍可能巨大 VkDeviceSize

- commit：`7353b3b`
- 文件：`catvulkan/cat/vulkanRender.cpp:1249-1253`
- 风险：`assert(indexOffset >= 0)` 在 Release 失效，负数会 cast 成巨大 `VkDeviceSize`，可能 GPU 越界 / device lost。
- 建议：改成运行时守卫并校验 index type 对齐和 buffer size。

### W13 VK_SUBOPTIMAL_KHR 被当失败重试

- commit：`7ba65a6`
- 文件：`catvulkan/cat/simplevulkan.cpp:2216-2234`
- 风险：`VK_SUBOPTIMAL_KHR` 是可继续使用的成功态，当前 `err != VK_SUCCESS` 会 callback / retry，连续 suboptimal 5 次后 `abort()`。
