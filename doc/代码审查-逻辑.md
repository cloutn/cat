# cat 项目代码审查 — 逻辑维度

> 子 agent：逻辑专家
> 项目类型：自研 C++ Vulkan/GLES 渲染引擎（非 UE）
> 审查范围：整个项目源码（`cat/`、`catbase/`、`catui/`、`catvulkan/`、`catwindows/`），第三方除外

## 批次 1：对象 / 组件 / 场景 / 世界 / Skin / Animation / Transform / KeyFrame

### Critical

- [逻辑] `cat/object.h:77` — `const Object* skinRoot() const { return skinRoot(); }` 在 const 成员里调用 `skinRoot()`，因 `this` 为 `const Object*`，重载决议只会选到自身（const 版本）→ **无限递归 / 栈溢出**。修法：`return const_cast<Object*>(this)->skinRoot();`，或让 const 版本走自己的实现。
- [逻辑] `cat/skin.h:24` — `const Object* root() const { return root(); }` 同样的"const 调 const = 递归自身" → **无限递归 / 栈溢出**。和 `object.h:77` 是同一类错误。
- [逻辑] `cat/object.cpp:323-328` — `releaseObjectIDMap()` 中 `delete s_objectIDMap`，**但不置 NULL**。进程晚期再调 `_objectIDMap()`，或 `Object` 构造里 `objectByID(...)`，`if (NULL == s_objectIDMap)` 检查失效（仍指向已释放内存）→ **use-after-free**。修复：`delete s_objectIDMap; s_objectIDMap = NULL;`
- [逻辑] `cat/skin.cpp:73-86` — `generateJointMatrix` 中解引用 `m_inverseBindMatrices[i]`，但 `_loadMatrices` 当 accessor 不是 `r_32f / mat4` 或 `view->size` 不对时返回 NULL。同时 `m_inverseBindMatrixCount` 没有跟 `joints_count` 校对，出现"count > 0 但 ptr == NULL"路径，draw 时**必崩**。
- [逻辑] `cat/animationChannel.cpp:137-141` — `else if (time > frames[mid]->time())` 分支直接用 `frames[mid + 1]`。`assert(mid < frames.size() - 1)` 仅在 Debug 有效。Release 下 `binary_search2` 若返回最后一个元素而 `time > frames[last]`，**越界访问**。
- [逻辑] `cat/object.cpp:186-189` — `loadSkin` 用 `i` 同时索引 `m_childs[i]` 和 `node->children[i]`。但 `loadNode` 在 `node->children[i] == NULL` 时是 continue，不 push_back。如果 gltf 里有 NULL child，**两数组索引错位 → 越界 / 错位赋值**。

### Warning

- [逻辑] `cat/object.cpp:165-175` — `parentGlobalMatrixInverse()` 父为空时 `assert(false)` + 返回 identity。Release 下静默返回单位矩阵会让所有依赖父级 inverse 的拾取/编辑/Gizmo 行为错乱。
- [逻辑] `catbase/cat/transform.cpp:43-46` — `Transform::setByMatrix(...)` 改完 `m_move/m_scale/m_rotate` 后**缺 `invalidate()`**。再调 `matrix()` 仍返回旧矩阵。
- [逻辑] `cat/object.cpp:114-133` — `Object::draw()` 调 `globalMatrix()` 两次（line 120 和 line 129）。父子链上每次都重新沿父链递归求矩阵，O(depth × childCount)，且没有缓存。
- [逻辑] `cat/object.cpp:330-342` — `child(const char* objectName)` 是线性搜索，且与 `child(int index)` 重名重载，调用方写 `child(0)` 与 `child("foo")` 语义截然不同。极易调错。建议改 `findChildByName(...)`。
- [逻辑] `cat/object.cpp:345-363` — `childByID(id, recursive)` 默认参数 recursive 是 false。但 `Scene::objectByID` 调用时传 true。如果调用方忘传 `recursive==true`，永远找不到 ID，返回 NULL → 静默失败。
- [逻辑] `cat/scene.cpp:43-48` — `for (size_t i = 0; i < scene.nodes_count; ++i) { ...->loadSkin(node, env); }` 没有判 `object` 是否 NULL。若 `clearGltfNodeMap()` 已被调或 node 不在映射里，崩。
- [逻辑] `cat/scene.cpp:95-99` — `Scene::draw` 没判 NULL 就 `m_objects[i]->draw(...)`。同 `Scene::save`（line 65）。
- [逻辑] `cat/animationChannel.cpp:146` — `(after.time() - before.time())` 是 `uint` 减法，若两帧时间倒序 → wrap 到大整数，delta 离谱，动画跳跃。
- [逻辑] `cat/animation.cpp:42-57` — `Animation::update(double diff)` 中 `m_time` 累加 `diff`，单位含糊。后面 `static_cast<uint>(m_time)` 喂 channel；channel 内部 time 来自 `times[i]*1000`（毫秒）。如果 `diff` 单位是秒而不是毫秒，进度就是 1000x 错位。
- [逻辑] `cat/animationChannel.cpp:30-37` — 构造里对 `union { quaternion m_rotate; vector3 m_move; vector3 m_scale; }` 依次三次 clear()。union 只一段内存，结果是最后一次 clear（m_move）的位模式覆盖前两次。语义上是 UB。
- [逻辑] `cat/animationChannel.cpp:53` — `const int frameCount = timeAccessor->count;`。`count` 是 `cgltf_size`(size_t)，赋 int 截断。
- [逻辑] `cat/animation.cpp:33-38` — `Animation::load` 没判 `channel->target_node` 是否在 `env` 里。如果 target 没注册到 ID map，`m_target` 拿到 -1，后面 `apply()` 调 `objectByID(-1)` 返回 NULL 然后 return。Load 阶段没 warning，静默失败。
- [逻辑] `cat/skin.cpp:88-133` — `Skin::root()` 取 `m_joints[0]` 当 first joint，再沿父链回溯找"不在 joint 集合中的祖先"。fallback（line 124-130 取 depth 最大的）在多个等长链时不一定是真 root。

### Suggestion

- [逻辑] `cat/object.cpp:225-254` — `setRotate/setScale/setMove` 都有"输入 == 当前则 return"的快速路径，`==` 用浮点精确比较；浮点几乎不可能精确相等，这条快速路径基本是死代码。
- [逻辑] `cat/skin.cpp:33-35` — `new matrix[outputMatrixCount]` 当 count==0 时合法但浪费。
- [逻辑] `free/scl/matrix.h:204-218` — `mul(m1, m2)` 与 `mul(m1, m2, m3)` 内部用 `*this` 临时承载，结果是 `*this = *this * m1 * m2[ * m3]`，而非"返回 `m1*m2`"。建议改名 `mul_chain(...)`。
- [逻辑] `catbase/cat/transform.h:25` — `invalidate()` 是 public，外部能强制让 cache 失效；与 setter 失效语义重复。

## 批次 2：相机 / 包围盒 / Env / Material / Light / Mesh / Primitive / cgltf_util / yaml / Shader / ShaderCache / Skybox / Terrain / Grid

### Critical

- [逻辑] `cat/terrain.cpp:72` — `m_primitive->setIndices(m_indices, 3, ELEM_TYPE_UINT32);` 第二参数硬编码成 `3`，应是 `INDEX_COUNT`(=`(N-1)*(N-1)*2*3`)。**只画 1 个三角形**。明显是 debug 数值遗留。
- [逻辑] `cat/primitive.cpp:386-407` — `Primitive::setAttrs` 在 "attrCount > m_attrCount" 时 realloc `m_attrs`，**但不 realloc `m_attrBufferIndices`**。扩 attrCount 后**越界写入**。
- [逻辑] `cat/primitive.cpp:203` — `void* _shader = isPick ? m_pickShader->shader(render) : m_shader->shader(m_render);` `m_pickShader` / `m_shader` 任一为 NULL 即直接段错误。
- [逻辑] `cat/grid.h:9` — 声明 `~Grid();`，但 `cat/grid.cpp` **没有实现**。栈上 `Grid g;` 或 `delete grid;` → **链接错误**。
- [逻辑] `cat/env.cpp:56-61` `Env::getDefaultMaterial()` — 看实现是 new 一个 Material 返回。但 `cat/primitive.cpp:187` 取到 m_material，后续 Primitive 析构会 delete，违反 "default = singleton" 隐式契约 → 潜在 double-delete。

### Warning

- [逻辑] `cat/primitive.cpp:436-437` — `setVertices(verticesList ...)` 直接 `m_deviceVertexBuffers = new void*[m_attrCount]`，**不释放旧的**。重复调用 → 内存 + GPU buffer 双泄漏。
- [逻辑] `cat/primitive.cpp:470` — `if (m_deviceVertexBuffers[0] <= 0)` 在 `m_deviceVertexBuffers == NULL` 时直接解引用 NULL。
- [逻辑] `cat/primitive.cpp:80` — `int attrOffsets[1024] = { 0 };` 栈上 4KB 固定数组，gltf attr 数 > 1023 时越界，缺断言。
- [逻辑] `cat/primitive.cpp:617-618` — `vertexPositions(vector3* positions, ...)` 用 `positions[0].value_ptr()` + `m_vertexCount * sizeof(vector3)` 当总字节数。若编译器对齐插入 padding（`sizeof(vector3) > 12`），写入步长与 `vertexAttrs` 内 12 字节步长不一致，position 数据会错位。建议显式 `3 * sizeof(float) * count`。
- [逻辑] `cat/primitive.cpp:84` — `vertexCount = primitive.attributes[0].data->count;` 假定所有 attr count 一致；gltf spec 是要求一致，但缺失断言。
- [逻辑] `cat/primitive.cpp:361-369` `setTexture(filename)` — 命名暗示用 filename 创建材质，**实际只 new Material()，filename 完全没用**。
- [逻辑] `catbase/cat/cgltf_util.c:66-75` `cgltf_primitive_has_attr` 用 `_strnicmp` 做前缀匹配，会把 "POSITION" 与 "POSITIONS" 匹配上；传入 "TEXCOORD" 时会匹配 "TEXCOORD_0"。若日后定义 "JOINT_INVALID" 之类 attr 会假阳。
- [逻辑] `catbase/cat/cgltf_util.c:4-8` `cgltf_get_accessor_buffer` 不判 NULL，accessor / buffer_view / buffer 任意为 NULL 都崩。多数调用方未显式判空。
- [逻辑] `catbase/cat/cgltf_util.c:71` `_strnicmp` 是 MS-only API；项目跨平台需 `strncasecmp`，未见包装宏。
- [逻辑] `cat/shader.cpp:54-57` — `_loadfile` 打开失败 `return false;`，函数返回类型是 `char*`，`false` 隐式 → `(char*)0`，调用方拿到 NULL 但不检查直接传给 `render->createShader(NULL, ...)`。**静默失败**。
- [逻辑] `cat/shader.cpp:25-32` — `Shader::shader(render)` 先 `m_render = render`，然后 `render->releaseShader(m_deviceShader)`。如果上一次的 deviceShader 是用旧的 m_render 创建的，新 render 来 release 行为未定义。
- [逻辑] `catbase/cat/camera.cpp:115-131` `orbit_right` / `orbit_up` 末尾 `m_up = vector3::cross(right, front);` **没 normalize**；而 `rotate(...)` line 109 有 normalize。多次 orbit 后 m_up 长度会漂。
- [逻辑] `catbase/cat/camera.cpp:86-92` `Camera::move(d)` 用 `_front()` 单位向量做 `target = position + lookat`，**会强行把 target-position 距离重置为 1**。语义和"纯平移"不一致。
- [逻辑] `cat/env.cpp:94-107` `Env::releaseTextureFile(NULL)` 直接 `pTextureFile->name` 解引用 → 崩；缺 NULL 判断。
- [逻辑] `cat/env.cpp:148-153` `registerPickPrimitive` 用 `m_pickPrimitives.size()` 作 id，array 大小 1024 写死；超出后 `push_back` UB / assert。
- [逻辑] `cat/light.cpp:5-9` `Light::Light()` 仅初始化 `m_transform`，**`m_color` 未初始化** → 包含未定义 float 值。`color()` 一调就拿到垃圾。
- [逻辑] `catbase/cat/transform.cpp:22-33` `mul(scale_mat) → mul(rotate) → mul(move)` 给出 `S*R*T`。scl 用**行向量约定（v_row * M）**。如果将来误把矩阵 `transpose` 后丢给 shader（shader 普遍按列向量），会得到镜像/混乱结果。
- [逻辑] `cat/animationChannel.cpp:30-37` 与 `catbase/cat/keyFrame.cpp:12-17` 都是 union 三个 clear() 顺序调用。意图似乎是"清三种"，实际只清最后一种。

### Suggestion

- [逻辑] `catbase/cat/camera.cpp:12-26` 初始化列表顺序与成员声明顺序**不一致**，编译器 `-Wreorder` 会警告。
- [逻辑] `cat/shaderCache.cpp:23-66` cache key 把 macros 按输入顺序串起来。同一组 macro 不同顺序会算成不同 key，重复编译。建议 macros 入 cache 前 sort by name。
- [逻辑] `cat/shaderCache.cpp:111-117` `getPickShader` 直接复用 input shader 的 macros 加 `PICK`、去 `COLOR/TEXTURE`，但若 user shader 还依赖 `COLOR`/`TEXTURE` 触发别的代码路径，pick 阶段就跟 main 阶段不一致。
- [逻辑] `cat/material.cpp:14` ctor 没初始化 `m_env`。当前 `release()` 仅在 `m_textureFile != NULL` 时才用 m_env，路径上不会用到未初始化值；但严格按成员初始化要求，应在 init list 里置 NULL。
- [逻辑] `catbase/cat/yaml.h:163-176` `node_iterator::m_childID` 类型是 `size_t` 但构造取 `int`，`-1` 隐式 → `SIZE_MAX`。建议统一用 int。
- [逻辑] `cat/terrain.cpp:24-25` `x = row - TERRAIN_SIZE/2; y = -col + TERRAIN_SIZE/2;` int 除法导致地块不居中。一行 `(TERRAIN_SIZE - 1) / 2.0f` 即可。
- [逻辑] `catbase/cat/box.h:11` 构造 `Box(_min, _max)` 调 `ensureMinMax()` 自动交换，OK；注意 `setMinDirect` / `setMaxDirect` **跳过** ensureMinMax，写明"直接覆盖" OK。

### 条目统计（基于批次 1-2）

### 最严重的 5 个逻辑问题

1. **`cat/object.h:77` + `cat/skin.h:24` 两处 `const xxx() const { return xxx(); }` 形式无限自递归** — 任何 const 路径栈溢出。
2. **`cat/terrain.cpp:72` setIndices 第二参写死成 3** — 整个 terrain 只画 1 个三角形，明显 debug 残留。
3. **`cat/primitive.cpp:386-407` setAttrs 不同步 realloc `m_attrBufferIndices`** — 扩 attrCount 后写入越界。
4. **`cat/skin.cpp:73-86` + `cat/object.cpp:186-189` skin/loadSkin 索引错位与未判空** — 任何不规范 gltf 会崩。
5. **`cat/shader.cpp:54-57` `_loadfile` 失败返回 `false` 当 `char*`** — 静默 NULL 一路传到 GL/Vulkan 创建 API。

### 整体逻辑健康度

- **核心数据结构（Object/Skin/Animation）逻辑问题集中**：以索引错位、NULL 链式解引用、const 重载误用为主，多由 GLTF 加载失败/边界场景触发；不规范 gltf 几乎必爆。
- **数学约定有歧义**：`scl::matrix` 行向量约定 + `Transform` 的 `S*R*T` 顺序在跨 shader 时需要明确文档化，否则 transpose 一次就错。
- **缺失防御性判空**：渲染热路径多个函数（draw、setIndices、setVertices、release）对 NULL 输入直接解引用。
- **修复路径**：先把 5 个 Critical 修了；再扫一遍所有 `assert(false) + 默认行为` 的地方，要么改 bool 返回，要么 abort，避免 release 下静默通过；最后给"边界 case"加单元测试（empty gltf、NULL child、长 keyframe 链）。
