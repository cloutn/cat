### animationChannel.h / animationChannel.cpp

**Critical**
- [崩溃·空解引用] `cat/animationChannel.cpp:50-53` — `channel.sampler`、`sampler->input`、`sampler->output` 三层指针没判空。残缺 GLTF 中 sampler 可能 NULL（cgltf 不强制非空）。修复：依次判空 return。
- [崩溃·空解引用] `cat/animationChannel.cpp:69-78` — `cgltf_get_accessor_buffer` 在 buffer 未加载（外部 .bin 缺失）时返回 NULL；`times[i] * 1000` 与 `frameDatas[i*componentCount]` 必段错误。修复：判空 return。
- [崩溃·UB·union 不活跃成员] `cat/animationChannel.cpp:34-36` 与 `cat/animationChannel.h:33-38` — `union { quaternion m_rotate; vector3 m_move; vector3 m_scale; }` 在 C++ 中只允许一个成员有 active lifetime；构造函数依次调 `m_rotate.clear(); m_scale.clear(); m_move.clear();` —— 后两个操作的是非活跃成员，**严格意义上是 UB**。当前因为 quaternion / vector3 都是 POD 状 trivially copyable 类型可能不崩，但在 MSVC /sdl 或 GCC -fstrict-aliasing 下可触发优化错误。修复：union 改 struct，或只 init 第一个成员，剩下用 placement new 在 m_type 切换时构造。同样问题在 `keyFrame.h` 中。

**Warning**
- [越界] `cat/animationChannel.cpp:139` — `assert(mid < frames.size() - 1);` release 失效；若由于浮点比较或时间 wrap，binary_search2 返回 `frames.size()-1` 而 `time > frames[mid]->time()`，下面 `frames[mid+1]` 越界写。修复：`if (mid + 1 >= frames.size()) { mid = frames.size() - 2; }` 或直接 if-return。
- [类型/隐式窄化] `cat/animationChannel.cpp:53` — `const int frameCount = timeAccessor->count;` count 是 `cgltf_size`(size_t)；超 INT_MAX 截断（虽不太现实）。
- [边界·除零] `cat/animationChannel.cpp:146` — `delta = (time - before.time()) / static_cast<float>(after.time() - before.time());` 如果 `after.time() == before.time()`（两帧时间戳重复，gltf 编辑器可能产生），得到 inf/nan，slerp/lerp 输出污染。建议 `if (after.time() == before.time()) { _set(after); return; }`。
- [生命周期·目标对象] `cat/animationChannel.cpp:191-204` — `Object::objectByID(m_target)` 拿到 Object 后**没有** weak ref，若该 Object 在动画播放期间被释放（虽然 ID map 会清理）但帧间状态未刷新仍可能取到陈旧。当前 `objectByID` 走 hash map 查询，删除 Object 时 `_objectIDMap().del(this)` 会清，相对安全；但若 Object 跨线程 delete + apply 即数据竞争。
- [防御] `cat/animationChannel.cpp:78` — `static_cast<uint>(times[i] * 1000)` 若 times[i] 异常（NaN/负数）转 uint 是 UB。建议 clamp。

**Suggestion**
- [防御] `cat/animationChannel.cpp:189-205` 与 161-176 — 各 switch 加 `default: break;`（已有，但 _resetTransform 同模式 OK）。
- [可读] `cat/animationChannel.h:33-38` — union 改成 `struct { quaternion rot; vector3 v; }` 浪费内存但无 UB；或改 `std::variant`。

### vulkanRender.h / vulkanRender.cpp

**Critical**

- [崩溃/UB] `catvulkan/cat/vulkanRender.cpp:287, 351` — `releaseVertexBuffer` / `releaseIndexBuffer` 末尾 `delete vertexBuffer;` / `delete indexBuffer;`，参数静态类型为 `void*`。**`delete` 一个 `void*` 是 C++ 未定义行为**（不调析构、实际平台行为不可保证）。当前 svkBuffer 是 POD 没有析构副作用，MSVC 通常仅释放堆内存，但语义错误。修复：先 `static_cast<svkBuffer*>(vertexBuffer)` 再 delete。
  - 调用链：所有 mesh release 路径。

- [崩溃/UAF] `catvulkan/cat/vulkanRender.cpp:727-756 endScenePass` — `svkQueueSubmit` 在 line 751 使用 `m_frames[m_prevFrameIndex].imageAcquireSemaphore`。**`m_prevFrameIndex` 构造时初值 -1**（line 55），首帧若执行到 endScenePass 而 beginDraw 未把它赋成 ≥0 的值（路径上 beginDraw 在第一次 swap 后才被调，详见 line 584），`m_frames[-1]` 即数组负索引越界。修复：判 `if (m_prevFrameIndex < 0) m_prevFrameIndex = m_frameIndex;` 或者 endScenePass 用本帧 acquire semaphore。
  - 调用链：`init → beginScenePass → endScenePass` 首帧。

- [崩溃/UAF] `catvulkan/cat/vulkanRender.cpp:220-272 ~VulkanRender` — 析构函数**没有调用 `vkDeviceWaitIdle`/`waitIdle()`** 就开始销毁 pipeline / buffer / fence / semaphore / framebuffer / image / swapchain。上一帧的 GPU 工作（drawIMGUI、endScenePass 提交的 cmd buf）仍可能 in-flight。validation layer 必报错；real device 上可触发 device lost 或 USE-AFTER-FREE。修复：函数入口 `if (m_device.device) svkDeviceWaitIdle(m_device);`。

- [崩溃] `catvulkan/cat/vulkanRender.cpp:246-260 ~VulkanRender` — `m_commandAllocator[i]->release(m_device)`、`m_pickCommandAllocator->release(m_device)`、`svkFreeCommandBuffer(m_device, m_pickCommandBuffer)` 等**都没有判空保护**。若 `init()` 在创建这些对象之前失败（svkCreateInstance/Device/Surface 任一失败），m_isInit 仍 false，但堆/栈对象析构照样运行，对 NULL 解引用即崩。修复：对每个指针 `if (NULL != ...)`，对 VkXxx handle 检查 `VK_NULL_HANDLE`。

- [崩溃] `catvulkan/cat/vulkanRender.cpp:541-556 createShader(int)` — switch 内所有分支 `assert(false)`，但函数仍 `new svkPipeline` 并返回**未初始化的指针**（构造里没有清零，svkPipeline 包含原始 handle 成员）。caller 后续 vkCmdBindPipeline 用垃圾 handle 必崩 + 64 字节泄漏。修复：`assert(false); delete pipeline; return NULL;`，或彻底删除该 overload。

- [崩溃/内存破坏] `catvulkan/cat/vulkanRender.cpp:934-945 _fillDynamicOffsets` — `memcpy((byte*)(m_drawContext.uniformBufferMapped) + m_frameUniformBufferOffset, ...)`，**未检查 `m_frameUniformBufferOffset` 是否超 buffer 容量** (`minUniformBufferOffset * MAX_OBJECT_PER_FRAME * MAX_MATRIX_PER_FRAME` ≈ 16 MB)。一旦单帧 draw 调用数 × 矩阵数超过该额度，立即写穿映射内存 → 堆破坏或 GPU 读到非法地址。修复：bound check + assert + early return。

- [崩溃/UAF] `catvulkan/cat/vulkanRender.cpp:1265-1285 recreateSwapchain` — 销毁/重建 main render target、pickRenderTarget 时**没有 reset `m_commandAllocator[i]` 与 `m_pickCommandAllocator`**。原 secondary command buffer 在 begin/inheritance 里绑定的 `framebuffer`/`renderPass` handle 已失效，下一次 `vkCmdExecuteCommands` 引用即 UAF。修复：每个 allocator 调 `reset(m_device)` 或 release+init。`m_drawContext.framebuffer` 同样陈旧（虽然在 begin*Pass 时会被重新赋值，但 endScenePass 路径中如果中途 resize 即 stale）。

- [崩溃] `catvulkan/cat/vulkanRender.cpp:1271 recreateSwapchain` — `m_onSurfaceResize(m_surface.width, m_surface.height);` 如果 caller 没通过 `setOnSurfaceResize` 设置，`scl::class_function` 调用无 callee 通常会崩。修复：`if (m_onSurfaceResize) m_onSurfaceResize(...);`。

- [崩溃] `catvulkan/cat/vulkanRender.cpp:1300-1318 drawIMGUI` 与 `:1196-1247 draw2` — 未使用 bindCommandBuffer 路径下 `m_drawContext.commandAllocator->alloc()` 不判空。若 caller 调用前未 begin*Pass，`m_drawContext.commandAllocator` 仍是 memclr 后的 NULL，解引用即崩。drawIMGUI 仅查 `_minimized()`，draw2 line 1193 仅查 renderPass。修复：函数入口同时检查 `commandAllocator`。

**Warning**

- [资源/Vulkan spec] `catvulkan/cat/vulkanRender.cpp:1287-1291 recreateSurface` — `svkDestroySurface` 然后立即 `svkCreateSurface`，**没有先销毁 swapchain**。Vulkan spec: `VkSwapchainKHR` 必须先于对应 `VkSurfaceKHR` 销毁；否则 validation 报错 / 部分 driver 直接崩。后续 `presentCallback` 才会调 `recreateSwapchain`，竞态/顺序脆弱。修复：先 `svkDestroySwapchain` 再 destroy surface，重建后立刻 `_createMainRenderTarget`。

- [资源/隐式假设] `catvulkan/cat/vulkanRender.cpp:1265-1285 recreateSwapchain` — surface 改变时**不重新创建 `m_pickPassImageCPUBuffer`**（line 1280-1281 已注释）。当前 `endPickPass` 仅 copy 1x1，OK；但代码注释暗示原本要拷贝整 surface，如果今后改回，buffer 容量不再够（按旧 surface size 分配）→ vkCmdCopyImageToBuffer 越界写 device memory → device lost。建议无条件 recreate 或加 assert。

- [窄化/溢出] `catvulkan/cat/vulkanRender.cpp:122` — `m_surface.width * m_surface.height * 4` int 计算；16K (15360×8640) 已 > INT_MAX，结果负或溢出后 svkCreateBuffer 的 size 参数错误。修复：`(size_t)w * h * 4`。

- [窄化] `catvulkan/cat/vulkanRender.cpp:1229 vkCmdBindIndexBuffer` — `indexOffset` 是 `const int` 形参，函数签名要求 `VkDeviceSize` (uint64)。caller 传 -1（惯用"全部"占位）会被隐式扩为 0xFFFF…FFFF → GPU 读越界 → device lost。修复：`assert(indexOffset >= 0);` 并改用 `VkDeviceSize`/uint64。

- [Vulkan/state] `catvulkan/cat/vulkanRender.cpp:1024-1031 _createMainRenderTarget` — `m_frameIndex = 0` 覆盖了之前的状态，但 `m_prevFrameIndex` 不复位（可能保留 recreate 前的旧帧索引甚至 ≥ 新 frameCount）。endScenePass 用 m_prevFrameIndex 即越界。修复：`m_prevFrameIndex = -1;` 同时如上 endScenePass 守护。

- [线程] `catvulkan/cat/vulkanRender.cpp:861-877 _prepareDescriptorSet` — `m_descriptorAllocators.add/get`、`m_descriptorSetCache.add/get`、`m_pipelines.add/get` 均无锁。`draw2` 名义上单线程；但 `presentCallback`（line 483）由 `svkPresent → vkQueuePresentKHR` 间接触发，可能在驱动回调线程调用 `recreateSwapchain`。文档化"renderer 必须单线程"或加锁。

- [资源膨胀] `catvulkan/cat/vulkanRender.cpp:836-883` 中的 `m_descriptorSetCache` 与 `m_pipelines`、`m_descriptorAllocators` 都**只增长、无 evict**。`MAX_DESCRIPTOR_SET_CACHE_SIZE * MAX_CONFLICT` (=16384) 满后再 add 行为未定义，可能 assert 或丢数据。长跑场景必踩。

- [冗余] `catvulkan/cat/vulkanRender.cpp:66-80 ctor` — `memclr(m_device); memclr(m_surface);` 在 66-67 与 69-70 重复两次。无害但拷贝粘贴错误。

**Critical**

### 最严重的 5 个问题（必须立即修复）

1. **`cat/object.h:77` + `cat/skin.h:24` 两处 const 方法无限自递归** —— `const Object* skinRoot() const { return skinRoot(); }` 和 `const Object* root() const { return root(); }` 都 call 自身。任何走到 const path 的代码立刻栈溢出崩溃。修复极简：调非 const 重载并 const_cast。

2. **`cat/shaderMacro.cpp:72-81` `assign(const ShaderMacro*, int)` 写错变量名** —— 在 `m_macros.clear()` 之后用 `add(m_macros[i])` 而不是 `add(macros[i])`。读越界（已清空数组）+ 完全错误的语义。一旦此重载被调用即崩。

### 系统性问题

- **指针生命周期完全没有 ownership 模型**：父子 Object 之间是 raw pointer，删一个 child 不会通知 parent；shader cache、material、texture 之间循环引用且 ownership 不明。建议引入弱引用或 ownership policy 注释。
- **静态 / 全局 Vulkan / GL 状态在退出时顺序未定义**：`s_objectIDMap`、`TextureFile::empty()`、`shaderCache` 与 `IRender` 的析构顺序不显式约束，进程退出 crash 风险高。
- **多线程未明确**：`ObjectIDMap`、`scl::hash_table`、Vulkan resource cache 都没锁。当前主线程 only 但缺乏文档化和 thread-affinity 检查。
- **错误处理偏向 assert**：大量 `assert(false)` 在 release 下静默失效，关键失败路径走错误分支后继续执行，掩盖问题。建议关键 assert 改为 `abort()` 或 log + early return。
- **`void*` 接口削弱类型安全**：`IRender` 的 buffer/texture/shader 全用 `void*`，`delete void*` 这种 UB 就是直接后果。建议用 opaque handle 类型。
